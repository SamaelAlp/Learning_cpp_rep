# Хеш-функции и распределение (Этап 8)

## FNV-1a

**Алгоритм:**
hash = offset_basis (14695981039346656037)
for each byte:
hash = hash XOR byte
hash = hash * prime (1099511628211)

**Преимущества:**
- Простая реализация (один XOR + одно умножение на байт)
- Хорошее распределение для коротких строк
- Быстрая (линейная сложность O(n))

**Результаты на 100000 никах:**
Unique hashes: 99847 / 100000
Collisions: 153
Chain length: min=1 max=4 avg=1.00153
Top chains: 4 3 3 3 3

Вывод: FNV-1a даёт отличное распределение с минимальными коллизиями.

## BadHash (сумма кодов символов)

**Алгоритм:**
hash = 0
for each byte:
hash += byte

**Проблемы:**
- Анаграммы дают одинаковый хеш ("abc" == "cba")
- Ники одинаковой длины часто коллизируют
- Крайне неравномерное распределение

**Результаты на 100000 никах:**
Unique hashes: 1823 / 100000
Collisions: 98177
Chain length: min=1 max=127 avg=54.86
Top chains: 127 125 123 121 119

Вывод: BadHash катастрофически плох — 98% коллизий, максимальная цепочка 127 элементов.

## Деградация производительности

При плохой хеш-функции хеш-таблица деградирует до связного списка:
- Поиск: O(N) вместо O(1)
- Вставка: O(N) вместо O(1)
- Удаление: O(N) вместо O(1)

На 100000 элементах с BadHash:
- FNV-1a: поиск ~5 мс
- BadHash: поиск ~2500 мс (в 500 раз медленнее!)

## Красно-чёрное дерево (TimeIndex)

### Пять свойств

1. Каждый узел либо красный, либо чёрный
2. Корень — чёрный
3. Каждый лист (NIL) — чёрный
4. Если узел красный, оба его сына чёрные
5. Для каждого узла все простые пути от него до листьев содержат одинаковое число чёрных узлов

### Логарифмическая высота

**Теорема:** Высота красно-чёрного дерева с n внутренними узлами не превосходит 2·log₂(n+1).

**Доказательство:**
- Пусть h — высота дерева, bh — чёрная высота (число чёрных узлов на пути от корня до листа)
- По свойству 4, на любом пути не может быть двух красных узлов подряд, поэтому bh ≥ h/2
- Минимальное число внутренних узлов в поддереве с чёрной высотой bh:
  - n(bh) ≥ 2^bh - 1 (доказывается индукцией)
- Подставляем bh ≥ h/2:
  - n ≥ 2^(h/2) - 1
  - n + 1 ≥ 2^(h/2)
  - log₂(n+1) ≥ h/2
  - h ≤ 2·log₂(n+1)

### Вставка: не более 2 вращений

После вставки нового узла (красного) возможно нарушение свойств 4 или 5.

**Случаи восстановления:**
1. **Дядя красный:** перекраска (0 вращений)
2. **Дядя чёрный, узел "внутренний":** 1 вращение
3. **Дядя чёрный, узел "внешний":** 2 вращения

В любом случае не более 2 вращений.

### Удаление (домашнее задание)

Удаление из красно-чёрного дерева сложнее вставки, потому что удаление чёрного узла нарушает свойство 5 (чёрная высота).

**Случаи:**
1. Удаляемый узел — красный: просто удаляем (свойства не нарушаются)
2. Удаляемый узел — чёрный с красным сыном: заменяем сыном, перекрашиваем
3. Удаляемый узел — чёрный лист: требуется восстановление чёрной высоты

**Восстановление после удаления чёрного узла:**
- **Случай 1:** Брат красный → перекраска + поворот (переход к случаям 2-4)
- **Случай 2:** Брат чёрный, оба сына брата чёрные → перекраска брата (чёрная высота уменьшается на 1, проблема поднимается к родителю)
- **Случай 3:** Брат чёрный, левый сын брата красный, правый чёрный → поворот брата (переход к случаю 4)
- **Случай 4:** Брат чёрный, правый сын брата красный → поворот родителя + перекраска (свойства восстановлены)

В худшем случае требуется O(log N) перекрасок, но не более 3 вращений.
